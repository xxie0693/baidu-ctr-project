# 模型评估报告

## 1. 基础信息
- **项目名称**：百度广告点击率（CTR）预测
- **任务类型**：二分类预测（预测用户是否点击广告，0为未点击，1为点击）
- **模型名称**：LightGBM（主模型）、逻辑回归 Logistic Regression（基线）、Wide & Deep（深度学习对比模型）

## 2. 数据集描述
- **输入特征**：
  - 总特征数：16 个
  - 类别特征（14个）：banner_pos, site_id, app_id, device_type, device_conn_type, C1, C14-C21（高基数类别特征）。
  - 数值特征（2个）：hour_of_day（曝光小时）, day_of_week（星期几）。
- **数据集的划分**：
  - 采用分层抽样（Stratified Sampling），按 7:2:1 划分。
  - **训练集**：2,830,027 条（占 70%）。
  - **验证集**：808,619 条（占 20%）。
  - **测试集**：404,250 条（占 10%）。
- **标签分布**：正样本（click=1）占比约 17%，负样本（click=0）占比约 83%。存在明显的**类别不平衡**问题。
- **高方差/高偏差讨论**：
  - 逻辑回归（LR）呈现高偏差（欠拟合），无法捕捉非线性特征交互。
  - LightGBM 通过正则化参数（如 max_depth=8, feature_fraction=0.8）有效控制了高方差（过拟合），在验证集和测试集上的 AUC 差距极小。

## 3. 评估指标
- **核心指标**：**AUC-ROC**（Area Under Curve）。在 CTR 预估及广告竞价场景中，模型的主要任务是给广告排序，AUC 能很好地衡量模型将正样本排在负样本前面的能力，且不受样本不平衡影响。
- **辅助指标**：**LogLoss**（对数损失）。衡量预测概率与真实概率的分布差异。

## 4. 评估结果
经过测试集评估，各模型表现如下：

| 模型名称 | AUC (越高越好) | LogLoss (越低越好) | 评价 |
|---------|--------------|-----------------|------|
| 逻辑回归 (LR) | 0.6120 | - | 作为基线，表现较弱。 |
| **LightGBM** | **0.7337** | **0.4050** | 表现最优，为最终落地模型。 |
| Wide & Deep | 0.7187 | - | 深度学习模型，仅训练3个Epoch，潜力大。 |

## 5. 模型性能分析与讨论
- **对比分析**：
  - LightGBM 相比 LR 基线，AUC 提升了约 12 个百分点，说明特征之间存在强烈的非线性交叉（如“时段 × 广告位”的交互），传统线性模型无法有效拟合。
  - 深度模型（W&D）在无 GPU 环境下训练时间略长，但仅 3 个 Epoch 就逼近了 LightGBM，说明端到端学习具有很好的泛化能力。
- **误差分析**：
  - 抽取了模型预测错误（高分底、低分高）的样本进行排查。发现**冷启动媒体/应用**（曝光量极低的站点）和**长尾设备**的预测误差较大。因为模型无法从极少的曝光中充分学到该媒体特征，容易给出偏向大盘均值的预测。
- **过拟合/欠拟合讨论**：
  - LightGBM 训练集 AUC（0.736）与测试集 AUC（0.733）非常接近，表明模型没有出现明显的过拟合。得益于 Early Stopping 和树的深度限制，模型泛化能力良好。

## 6. 环境与部署考量
- **推理速度**：
  - **批量推理**：在 Mac (CPU) 环境下，批量处理 1000 条样本仅需 **2.25 毫秒**，平均单条计算耗时约 **0.002 毫秒**。完全满足线上广告竞价系统毫秒级的响应要求。
  - **单次请求**：若通过单条接口调用，由于 Python 与 C++ 底层交互开销，耗时约 100 毫秒；线上部署时将采用 Batch 聚合请求，可完美规避此问题。
- **模型大小**：
  - 保存的 LightGBM 模型文件体积仅 **1.34 MB**，极易加载到内存中常驻，几乎不占用服务器存储资源。
- **资源消耗**：
  - **训练期**：LightGBM 在 CPU 上仅需 **23 秒**即可完成 280 万样本的训练，内存峰值约 2GB。
  - **推理期**：无需 GPU 资源，单机 CPU 单核即可支撑极高的 QPS（每秒查询率）。
