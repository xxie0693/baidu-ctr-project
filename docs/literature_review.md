## 二、论文一：Wide & Deep Learning for Recommender Systems

**基本信息**

| 项 | 内容 |
|----|------|
| 作者 | Heng-Tze Cheng 等（Google） |
| 发表 | 2016, DLRS Workshop |
| 引用量 | 5000+ |
| 应用场景 | Google Play 应用推荐 |

### 2.1 核心问题

传统推荐系统面临**记忆（Memorization）**与**泛化（Generalization）**的权衡：

- **记忆**：学习训练数据中频繁共现的特征组合。线性模型（如 LR）通过交叉积特征擅长记忆，但无法泛化到未见组合。
- **泛化**：基于特征的语义相似性探索新的特征组合。深度神经网络通过嵌入擅长泛化，但可能过度泛化导致推荐不相关。

**单独使用任一种都有局限**。Google 的解决方案是**联合训练**。

### 2.2 模型结构

```text
        Wide 部分                    Deep 部分
    ┌──────────────┐          ┌──────────────────┐
    │ 交叉积特征    │          │  稀疏特征嵌入     │
    │ (用户已装应用 │          │  (用户属性、      │
    │  × 曝光应用)  │          │   应用属性、      │
    └──────┬───────┘          │   上下文特征)     │
           │                  └────────┬─────────┘
           │                           │
           │                  ┌────────▼─────────┐
           │                  │ 隐藏层 (ReLU)     │
           │                  │ 隐藏层 (ReLU)     │
           │                  └────────┬─────────┘
           │                           │
           └──────────┬────────────────┘
                      │
                ┌─────▼─────┐
                │ 输出层     │
                │ (Sigmoid)  │
                └───────────┘
```

**Wide 部分**：

$$ y_{wide} = w^T [x, \\phi(x)] + b $$

其中 $\\phi(x)$ 是交叉积变换，如 `AND(user_installed_app=netflix, impression_app=pandora)`。仅当两个特征同时出现时取 1。

**Deep 部分**：

$$ y_{deep} = \\sigma(W_{deep}^T a^{(l)} + b_{deep}) $$

其中 $a^{(l)}$ 是最后一层隐藏层的激活值。

**联合训练**：

$$ P(y=1|x) = \\sigma(w_{wide}^T [x, \\phi(x)] + w_{deep}^T a^{(l)} + b) $$

### 2.3 关键贡献

1. **联合训练框架**：Wide 与 Deep 部分**同时**反向传播，而非集成式（分别训练后融合）。
2. **Wide 部分只需少量交叉积特征**：不再需要全特征工程，Deep 部分承担大部分工作。
3. **解决冷启动**：Deep 部分通过嵌入泛化到新特征组合，缓解了纯 Wide 模型对训练数据覆盖的依赖。

### 2.4 实验效果

在 Google Play 数据集上：

| 指标 | Wide 单独 | Deep 单独 | Wide & Deep |
|------|----------|----------|-------------|
| AUC | 基准 | +0.5% | **+1.0%** |
| 应用下载量 | 基准 | +2% | **+3.9%** |

### 2.5 对百度广告 CTR 的启示

- **搜索广告场景中，Wide 部分可承载交叉积特征**：如 `广告位 × 时段`、`站点类目 × 设备类型`。
- **Deep 部分学习匿名特征 C1-C21 的高阶交互**：百度广告数据中 C1-C21 是匿名类别特征，深度网络可以自动学习其嵌入表示。
- **联合训练 > 集成**：本项目的模型融合方案应优先考虑联合训练。

## 三、论文二：Deep Interest Network for CTR Prediction

**基本信息**

| 项 | 内容 |
|----|------|
| 作者 | Guorui Zhou 等（Alibaba） |
| 发表 | 2018, KDD |
| 引用量 | 3000+ |
| 应用场景 | 阿里妈妈展示广告 |

### 3.1 核心问题

传统深度 CTR 模型将用户历史行为压缩为**固定长度向量**，无法表达用户**多样化兴趣**。

举例：一个用户历史购买过 {毛衣, 牛仔裤, 耳机, 键盘}。当推荐候选广告是"外套"时，模型应**重点关注**毛衣、牛仔裤相关的行为，而不是耳机、键盘。固定向量无法实现这种"局部激活"。

### 3.2 模型结构

```text
用户历史行为序列: {item_1, item_2, ..., item_N}
候选广告: item_target
              │
              ▼
    ┌──────────────────┐
    │  注意力单元       │
    │  对每个 item_i    │
    │  计算权重 w_i     │
    └────────┬─────────┘
             │
             ▼
    用户兴趣表示 = Σ w_i · emb(item_i)
             │
             ▼
    ┌──────────────────┐
    │  拼接 + 全连接    │
    └──────────────────┘
```

**局部激活单元**：

$$ v_U(A) = \\sum_{i=1}^{N} w_i \\cdot v_i = \\sum_{i=1}^{N} g(v_i, v_A) \\cdot v_i $$

其中：
- $v_i$ 是历史行为 item 的嵌入
- $v_A$ 是候选广告的嵌入
- $g(v_i, v_A)$ 是注意力函数（即 activation unit）
- $w_i$ 是**针对特定候选广告动态计算**的权重

### 3.3 关键贡献

1. **局部激活单元（Local Activation Unit）**：根据候选广告动态调整用户兴趣表示，实现"兴趣多样性"表达。
2. **Mini-batch Aware 正则化**：仅对 batch 中非零特征的参数计算 L2 范数，解决十亿级参数的计算问题。
3. **数据自适应激活函数（Dice）**：推广 PReLU，根据输入分布自适应调整整流点。

### 3.4 对百度广告 CTR 的启示

- **百度广告场景中用户点击行为具有多样兴趣**：一个用户可能在搜索"笔记本电脑"后又被推荐"手机壳"，DIN 的注意力机制可以建模这种多样兴趣。
- **DIN 需要用户行为序列数据**：Avazu 数据集**缺少用户 ID 与行为序列**，DIN 无法直接应用。但其中的**注意力机制思想**可以借鉴——例如对广告位、时段等上下文做 attention。
- **Mini-batch Aware 正则化**适用于本项目：Avazu 数据中 C1-C21 是稀疏类别特征，传统 L2 会计算大量零参数。

### 3.5 局限

- 需要**用户行为序列**，数据要求高
- 训练复杂度高，需要大规模分布式
- 冷启动用户效果有限

## 四、论文三：Field-aware Factorization Machines for CTR Prediction

**基本信息**

| 项 | 内容 |
|----|------|
| 作者 | Yuchin Juan 等（NTU） |
| 发表 | 2016, RecSys |
| 引用量 | 2000+ |
| 应用场景 | Criteo、Avazu 竞赛 |

### 4.1 核心问题

FM（Factorization Machines）为每个特征学习**一个**隐向量。但 CTR 数据中特征属于不同**域（field）**，同一特征与不同域的特征交互时，应有**不同的隐向量**。

举例：`男` 这个特征属于"性别"域，与 `电子` 域交互时是一个含义，与 `化妆品` 域交互时是另一个含义。

### 4.2 模型公式

**FM**：

$$ \\hat{y}_{FM}(x) = w_0 + \\sum_{i=1}^{n} w_i x_i + \\sum_{i=1}^{n} \\sum_{j=i+1}^{n} \\langle v_i, v_j \\rangle x_i x_j $$

每个特征 $i$ 只有一个隐向量 $v_i \\in \\mathbb{R}^k$。

**FFM**：

$$ \\hat{y}_{FFM}(x) = w_0 + \\sum_{i=1}^{n} w_i x_i + \\sum_{i=1}^{n} \\sum_{j=i+1}^{n} \\langle v_{i, f_j}, v_{j, f_i} \\rangle x_i x_j $$

每个特征 $i$ 学习**一组**隐向量 $\\{v_{i, f}\\}$，其中 $f$ 表示与之交互特征所属的域。

**复杂度对比**：

| 模型 | 参数数量 | 计算复杂度 |
|------|---------|-----------|
| Poly2 | O(n²) | O(n²) |
| FM | O(nk) | O(nk) |
| FFM | O(nkf) | O(nkf) |

其中 $n$ 为特征数、$k$ 为隐向量维度、$f$ 为域数。

### 4.3 关键贡献

1. **域感知的隐向量**：为每个特征学习多个隐向量，增强表达力。
2. **竞赛验证**：在 Criteo、Avazu 两个全球 CTR 竞赛中获得冠军。
3. **Kaggle 冠军方案**：Avazu 竞赛冠军使用了 FFM + GBDT 的混合方案。

### 4.4 实验效果

在 Criteo 数据集上：

| 模型 | LogLoss |
|------|---------|
| LR | 0.4525 |
| FM | 0.4471 |
| FFM | **0.4445** |

在 Avazu 数据集上：

| 模型 | LogLoss |
|------|---------|
| LR | 0.3898 |
| FM | 0.3855 |
| FFM | **0.3824** |

### 4.5 对百度广告 CTR 的启示

- **Avazu 竞赛冠军用 FFM，本项目数据集是 Avazu，FFM 是天然的强基线**。
- **高基数匿名特征 C1-C21 恰好适合 FFM**：每个 C 特征属于不同域，FFM 能为它们学习域感知嵌入。
- **FFM 作为特征工程后的强基线**，与 GBDT、深度学习模型对比。

### 4.6 局限

- **参数数量大**：O(nkf)，内存占用高
- **不支持连续特征自动交互**：需手动分箱
- **训练速度慢**：相比 FM 慢 f 倍

## 五、论文四：DeepFM — A Factorization-Machine based Neural Network

**基本信息**

| 项 | 内容 |
|----|------|
| 作者 | Huifeng Guo 等（华为诺亚方舟） |
| 发表 | 2017, IJCAI |
| 引用量 | 3000+ |
| 应用场景 | 华为应用市场推荐 |

### 5.1 核心问题

Wide & Deep 的 Wide 部分**仍需人工特征工程**（交叉积特征设计）。能否让 Wide 部分自动学习特征交互？

**DeepFM 的答案**：用 **FM** 替代 Wide 部分，自动学习低阶特征交互。

### 5.2 模型结构

```text
                    输入特征
                       │
         ┌─────────────┴─────────────┐
         │                           │
    ┌────▼────┐                ┌─────▼─────┐
    │   FM    │                │   Deep    │
    │ (低阶)  │                │  (高阶)   │
    └────┬────┘                └─────┬─────┘
         │                           │
         │    共享嵌入 (Embedding)   │
         │           ▲               │
         │           │               │
         │    稀疏特征输入            │
         └───────────┬───────────────┘
                     │
                ┌────▼────┐
                │ Sigmoid │
                └─────────┘
```

**核心创新**：FM 部分与 Deep 部分**共享同一套嵌入层**，无需人工特征工程。

$$ \\hat{y} = \\sigma(y_{FM} + y_{Deep}) $$

$$ y_{FM} = \\sum_{i=1}^{n} \\sum_{j=i+1}^{n} \\langle v_i, v_j \\rangle x_i x_j $$

### 5.3 关键贡献

1. **端到端训练**：无需任何人工特征工程。
2. **共享嵌入**：FM 与 Deep 共享嵌入层，降低参数数量，避免过拟合。
3. **同时学习低阶与高阶交互**：FM 学习二阶，Deep 学习高阶。

### 5.4 实验效果

在 Criteo 数据集上：

| 模型 | AUC | LogLoss |
|------|-----|---------|
| LR | 0.7895 | 0.4698 |
| FM | 0.7987 | 0.4631 |
| Wide & Deep | 0.7997 | 0.4623 |
| **DeepFM** | **0.8025** | **0.4598** |

### 5.5 对百度广告 CTR 的启示

- **DeepFM 是本项目的首选基线模型**：无需人工交叉积特征，端到端训练，效果优于 Wide & Deep。
- **共享嵌入适合高基数特征**：C1-C21 共享同一套嵌入，降低参数量。
- **与 FFM 互补**：FFM 强在域感知，DeepFM 强在端到端，两者对比有意义。

## 七、对本项目的指导

### 7.1 特征工程阶段（第二阶段）

参考 FFM 与 DeepFM 的思想：

1. **构造交叉特征**：广告位 × 时段、站点类目 × 设备类型、站点 × 广告位
2. **类别特征编码**：Target Encoding + 嵌入（为深度学习准备）
3. **高基数特征处理**：device_id、device_ip 使用哈希分桶

### 7.2 建模阶段（第三阶段）

**优先顺序**：

| 优先级 | 模型 | 理由 |
|-------|------|------|
| 1 | **LR** | 基线，可解释性强 |
| 2 | **LightGBM / XGBoost** | 树模型，自动特征选择，工程效果好 |
| 3 | **FM / FFM** | 稀疏特征交互，Avazu 竞赛验证 |
| 4 | **Wide&Deep / DeepFM** | 端到端，无需人工特征 |
| 5 | **模型融合** | Stacking 树模型 + 深度模型 |

### 7.3 模型融合思路

参考 Wide&Deep 的**联合训练**思想，而非简单集成：

- **Stacking**：树模型输出作为深度模型的额外输入
- **Blending**：分别训练 LR、GBDT、FM，用 LR 融合预测结果

### 7.4 可解释性分析

- **LR 与 FFM**：基于特征系数解释
- **树模型**：基于 SHAP 值
- **深度模型**：基于注意力权重（DIN 类模型）
