## 一、本周核心工作内容

本周工作重心从第一阶段的“数据工程治理”平稳过渡到“数据业务洞察与存储优化”，完成了数据查询底座搭建与深度探索性分析（EDA）。具体工作如下：

1. **搭建 SQLite 星型模型与索引优化**
   - 针对 4000 万级记录，设计了包含 1 张事实表（`fact_impressions`）和 4 张维度表（广告位、媒体、设备、时间）的星型模型。
   - 编写 `sqlite_loader.py`，通过 Dask 流式分块导入，解决了单机内存无法一次性写入千万级数据的痛点；并为高频查询字段建立了索引，将聚合查询时间控制在秒级。

2. **研发 Python-SQLite 交互组件**
   - 封装了 `SQLiteClient` 工具类，实现了 SQL 查询结果与 Pandas DataFrame 的无缝转换。
   - 编写了核心 SQL 查询脚本，完成了全局曝光、各广告位 CTR 对比、全天时段趋势等基础数据分析。

3. **实现基于 IQR 法则的异常值处理**
   - 针对原始数据多为类别字段的特点，在第一阶段暂缓了连续指标异常检测。
   - 本阶段在 `build_features.py` 中，对聚合出的 CTR、曝光量等连续统计特征实装了 **IQR（四分位距）截断平滑**。有效防止了少量长尾极值（如点击率 100% 的小流量媒体）对后续模型梯度的干扰。

4. **产出 8 张核心 EDA 可视化图表与报告**
   - 开发了 `eda_visualizer.py`，通过图表解决业务问题。针对长尾分布导致的饼图标签重叠问题，改用横向条形图并合并长尾标签。
   - 覆盖了：时段趋势、广告位对比、媒体类型对比、设备分布、工作日/周末对比、类目对比、转化漏斗及数值特征相关性热力图。

## 二、核心业务洞察发现

通过 SQL 聚合与 EDA 分析，得出了几条对后续广告投放有直接指导意义的结论：

1. **时段偏好明显**：凌晨 1:00-2:00 的点击率（CTR）最高（突破 18%），而上午通勤时段（8:00-10:00）跌至谷底。**建议**：高转化广告可尝试在深夜长尾时段扩量。
2. **头部与长尾效应**：`banner_pos=0` 和 `1` 占据了 99.9% 的曝光，是全站基本盘；但少部分长尾广告位（如位置 7）的 CTR 高达 32%。**建议**：挖掘长尾高转化位置的潜力，作为模型特征输入。
3. **特征线性相关弱**：热力图显示原始数值特征与目标变量 `click` 几乎无线性相关性。**决策**：这直接否决了纯线性模型（如基础 LR）的效果上限，明确了第三阶段必须引入**交叉特征**与**树模型/深度模型**。

## 三、遇到的技术困难与解决方案

**困难 1：SQLite 事实表写入效率与内存溢出**
- **现象**：4000 万行数据直接通过 `to_sql` 写入会导致内存溢出（OOM）且速度极慢。
- **解法**：利用 Dask 的 `map_partitions` 思想，将数据按 63 个分区切分，通过 Python 分批提取（每块 50 万行）并采用 `if_exists='append'` 追加写入，最终稳定在几分钟内完成建库。

**困难 2：EDA 图表标签严重重叠**
- **现象**：在绘制设备类型分布时，由于设备 `1` 占比高达 92.3%，饼图上的其他类型标签完全重合，无法阅读。
- **解法**：重构绘图代码，弃用饼图，改用**横向柱状图**，并将占比低于 0.5% 的设备合并为“其他”类别，同时动态调整 X 轴范围给文字留白，彻底解决了重叠问题。
